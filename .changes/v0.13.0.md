## v0.13.0 - 2026-11-22

Three names are added, all in `gitenv`: `Home`, `NoHome` and `CommitMode`. No name is removed and no signature changes. Every name added is experimental, as every name of the module is. In `sandbox` only a darwin test is added, under Security below; nothing changes in `proc`, `load` or `service`. go.mod is unchanged. The tagged tree is 10,509 non-test Go lines outside `internal/` (`task size`), at its ceiling of 10,509, up 99 from v0.12.0's 10,410: 55 for `Home` and `NoHome`, 44 for `CommitMode`.

### For a v0.12.0 caller

Nothing changes for a program that calls none of the new names: `Env`, `Repo` and `ReadArgs` give what they gave, and no behaviour of the other packages moves.

### gitenv

- Added: `Home(dir)` is the `add` of `Env` for a child whose home is `dir`, `HOME=dir`, and `NoHome(empty)` that of a child with no home of the person's, `HOME=empty` and `GIT_CONFIG_GLOBAL=/dev/null`, so git reads no global configuration and libcurl no `.netrc` on any system. Each refuses a folder that is empty, relative or not clean, with an error naming which, and does no I/O: that `empty` is a folder of the account's alone that holds nothing is the caller's promise, which go-files' `MkdirFresh` or `MkdirPrivate` (v0.10.0) keeps. `/dev/null` is that exact string on every system, which Git for Windows maps to its null device; git reads `GIT_CONFIG_GLOBAL` from 2.32 on, and below that the empty folder is what holds. `NoHome` sets no `NETRC`, and a `NETRC` the caller adds itself is not undone. ssh takes `~` from the account whatever `HOME` says, so a child that reaches an ssh remote still needs a `GIT_SSH_COMMAND` of the caller's own. The ceiling is raised by the 55 lines this measures, from 10,410 to 10,465.
- Added: `CommitMode(fi, fileMode, head)` is the mode git commits for a regular file a program wrote, `100644` or `100755`, by git's own rule on every system: with the repository's `core.fileMode` true, the owner's exec bit, whoever runs; with it false, HEAD's mode for the path, or `100644` for a new path. Git for Windows sets `core.fileMode` false in every repository it makes, and Go reports no exec bit there, so a mode read from the exec bit alone flips an existing `100755` path to `100644` on Windows. The caller reads `core.fileMode` with `git config --type=bool --get core.fileMode` under `ReadArgs` and `Env`, absent meaning true. It refuses a file that is no regular file and a HEAD mode that is none of empty, `100644` and `100755`, a link's `120000` among them, and does no I/O. Its rows check it against `git add` and `git ls-files -s` on darwin, Linux and Windows.

### Security

- sandbox: a darwin row, `TestADescriptorTheFolderListingCannotStatDoesNotReachTheProgram`, holds the second half of v0.12.0's macOS descriptor fix, that the block finds the descriptors to mark by `/dev/fd`'s names alone. `/dev/fd` says `EBADF` to every stat of a POSIX shared memory descriptor, so `os.ReadDir`, which stats each entry, leaves one out, and v0.11.0's listing left it open into the exec. The row hands one to the command without close-on-exec and the program finds no descriptor above stderr; it is red every time with v0.11.0's listing put back under v0.12.0's lock, where the pipe row stays green. No product code changes.

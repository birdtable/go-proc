## v0.19.1 - 2026-11-27

No name is added, removed or moved, and no signature changes: the API check finds no break since v0.19.0. No promise in `api/contract.txt` changes, so this is a patch. What a name does changes in one place: on Linux, `sandbox.RunHolding`, and `sandbox.Check` with folders, now refuse up front ways a loader reaches a library that v0.19.0's load search never judged, and that v0.19.0 let through to fail at load behind the block, which breaks some callers (under Security below). Of v0.19.0's list of loads not promised refused up front, one is left in the docs: a library found where a loader's search order differs from the search's in some other way. What the block enforces does not change. Nothing changes in `proc`, `service`, `load` or `gitenv`, and no require in go.mod changes. The tagged tree is 12,132 non-test Go lines outside `internal/` (`task size`), at its ceiling of 12,132, up 67 (0.6%) from v0.19.0's 12,065, all for the new refusals. The full release checks ran on macOS at the tagged commit; vet and the tests, with the race detector, ran on Linux, macOS and Windows at the tagged commit in CI. No full release checks ran on Linux or Windows for this release.

### For a v0.19.0 caller

Nothing changes for a program that does not call `sandbox.RunHolding`, or `sandbox.Check` with folders, on Linux. There, a program is now refused with `ErrUsage` before anything is set, whatever folders are named, when it, or a library it loads, names a library by an audit or filter tag; under glibc, when a folder the search looks in has a `glibc-hwcaps` subfolder beneath no built-in folder of its loader; and when a path the search looks for is one on which a loader stops, such as a link loop. Such a program runs only once its libraries are reached by the search order alone. Under musl, a library found through a run path written with a closing slash is now judged by the name musl gives it: if that library is refused, name its folder, or one above it, in `Folders`. Callers on macOS and Windows see no change.

### Security
* sandbox: on Linux, `RunHolding` and `Check` with folders now refuse with `ErrUsage`, before anything is set, ways a loader reaches a library that v0.19.0's load search never judged, and that v0.19.0 let through to fail at load behind the block. A program or library naming a library by `DT_AUDIT`, `DT_DEPAUDIT`, `DT_FILTER` or `DT_AUXILIARY` is refused. Under glibc, a folder the search looks in is refused when its `glibc-hwcaps` subfolder has a real path beneath no built-in folder of the loader, since glibc looks there first, in an order set by the machine, and when that subfolder is a link loop or its real path cannot be told; a built-in folder's own `glibc-hwcaps`, as on Fedora, still passes. A path the search looks for that the kernel answers with an error other than not found, permission denied or not a folder, such as a link loop, a file that links to itself or a path past the kernel's length limit, is refused, where v0.19.0 passed over it and took a library in the next folder. glibc ends that folder list and goes on to the next list when the folder is there and the file in it answers such an error, and passes over a folder it cannot walk, such as a link loop or a folder past the kernel's length limit, to take the next folder's library, as v0.19.0 did; the search refuses both. musl stops the load on any such error but a name too long, which musl passes over and the search refuses too. Under musl a path of 512 bytes or more is still passed over, as musl does. Under musl the search now names a found library as musl does, the folder as written, a slash and the name, so for a library found through a run path written with a closing slash, `$ORIGIN` in that library and musl's 512-byte limit read the name musl reads, and a library musl takes outside the caller's folders and the built-in folders is refused, where v0.19.0 judged another name. Each other change only narrows what the search accepts. Under musl, a folder musl passes over once its closing slash is counted is passed over by the search too, so the next folder's library is the one judged. What the block enforces does not change. Breaking: a program that ran under v0.19.0 with such a library is now refused.

## v0.17.0 - 2026-11-25

One function is added, in `proc`: `HomeEnvCache`, with its error `ErrHomeCache`. No name is removed or moved, and no signature changes: the API check finds no break since v0.16.0. Every name added is experimental, as every name of the module is. Nothing changes in `sandbox`, `service`, `gitenv` or `load`, and no require in go.mod changes. The tagged tree is 11,458 non-test Go lines outside `internal/` (`task size`), at its ceiling of 11,458, up 75 from v0.16.0's 11,383, all for `HomeEnvCache`: its errors, its doc comment and the compare that keeps the two folders apart. The full release checks ran on macOS at the tagged commit; vet and the tests, with the race detector, ran on Linux, macOS and Windows at the tagged commit in CI. No full release checks ran on Linux or Windows for this release.

### For a v0.16.0 caller

Nothing changes for a program that does not call `HomeEnvCache`: every other name gives what it gave. A caller that kept a child's cache between runs by editing `HomeEnv`'s list can call `HomeEnvCache` instead, which also refuses a cache folder that is part of the fresh home, or holds it.

### Added
* proc: `HomeEnvCache(root, cache)` is `HomeEnv(root)` with `XDG_CACHE_HOME` pointed at `cache` itself, so a child keeps its cache in a folder the caller keeps between runs while the rest of its home is fresh. No other variable changes. On Linux and the BSDs `os.UserCacheDir` follows it; on macOS and Windows the system cache folder stays beneath `root`. It refuses, with `ErrHomeCache`, an empty or relative `root` or `cache`, a `cache` that is `root` or beneath it, and one that holds `root`. Folders are compared as written and cleaned, with case folded one letter to one letter and no link followed, so a caller that takes either folder from elsewhere resolves both the same way first. The caller judges the cache folder itself, and sets a tool's own cache variables, such as `GOCACHE`.

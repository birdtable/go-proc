## v0.11.0 - 2026-11-20

Three names are added: one in `proc` (`SystemEnv`) and two in `testenv` (`ContainMounts` and `ContainedMounts`). No name is removed and no signature changes. Every name added is experimental, as every name of the module is. Nothing changes in `load`, `sandbox` or `service`, and in `gitenv` only a helper of its own tests, which writes a program as testenv's tests do. go.mod and go.sum require the same modules at the same versions. The tagged tree is 12,971 non-test Go lines outside `internal/` (`task size`), at its ceiling of 12,971, up 461 from v0.10.0's 12,510: 9,656 in the runtime packages and 3,315 in `testenv`.

### For a v0.10.0 caller

Four behaviours change, besides the Security fix below, under which the tests of a contained run hold no capability. The rest of the release is names added and fixes, which a program or test that calls none of the new names doesn't see.

- `testenv.Contain` on Linux: a program whose file capabilities carry the effective flag, as a distribution's `ping` or `newuidmap` does, is refused at execve with `EPERM` in a contained run, where it started before. The namespace's init now empties the bounding set, so no program a test starts gains anything from its file capabilities. A test that must start such a program goes in a test binary whose `Main` is not given `Contain`.
- `testenv.Contain` on Linux, where the tests are uid 0 in the namespace (a test binary run as root, or under `unshare --map-root-user`): init sets and locks `SECBIT_NOROOT` and `SECBIT_NO_SETUID_FIXUP`, so neither the tests nor what they start regain the namespace's capabilities on execve. A test of such a run can no longer contain a test binary it starts: that binary's `Contained` skips with `Refused`, since Linux maps uid 0 of a new user namespace to uid 0 only for a process with `CAP_SETFCAP`.
- `testenv.Contain` on Linux: init makes itself not dumpable, so no test and nothing it starts opens init's memory or maps, or ptraces it.
- `proc.Bare` and `proc.Needed` keep `ProgramData` on Windows beside `SystemRoot`, and testenv keeps `PROGRAMDATA`, so a child started with them sees one variable more there. Elsewhere nothing changes.

### proc

- Added: `SystemEnv()` is this process's `NAME=value` for each variable a child on this system needs to start, or to find the system's own files, beyond `PATH`, `LANG` and the home names: `SystemRoot` and `ProgramData` on Windows, none elsewhere. Only names that are set are given; with none it is empty, never nil. Its names are among those `Bare` keeps and `Needed` names.
- Changed: `Bare` and `Needed` keep `ProgramData` on Windows. Without it System32's OpenSSH exits 255 before it writes a byte.

### testenv

- Added: `ContainMounts()` is `Contain`, and on Linux the tests keep `CAP_SYS_ADMIN` of Contain's own user namespace, effective and permitted, and no other capability. A test can mount a tmpfs or a bind mount in Contain's private mount namespace, and nothing of the host's. Nothing the tests start inherits the capability: from testenv's initialization, which runs before any package that imports testenv and before `TestMain`, the ambient and inheritable sets are empty on every thread, init sets and locks `SECBIT_NO_CAP_AMBIENT_RAISE`, and init sets `no_new_privs`, so no execve in the run gains from file capabilities or set-id bits. A package that does not import testenv may initialize before it, and a program that package's initialization starts holds the capability. Plain `Contain` leaves `no_new_privs` as the run has it. It needs a test binary built without cgo, and `-race` links cgo: there the run holds no capability. Elsewhere than Linux, `ContainMounts` is `Contain`.
- Added: `ContainedMounts(t)` is `Contained`, and skips unless the run holds the capability `ContainMounts` keeps, with the reason. Elsewhere than Linux it skips with `NoContainment`.
- Fixed: `(*Binary).Env` drops an entry with no name, such as `=v`, as `Clean` drops one, where it passed it to the run, so `Env(os.Environ()...)` works on Windows. Its doc now says that `Env` is the caller's own way past the pins: a `GOENV` or `HOME` it gives reaches the run. `Dir`'s doc says that it sets no `PWD`; a run that needs one takes `Env("PWD=" + dir)`.
- Fixed: `(*Binary).Install` holds `syscall.ForkLock` from its copy's open to its close, so a child another goroutine forks meanwhile no longer holds the copy open for writing, and a start of the copy no longer fails now and then with `text file busy` (ETXTBSY) on Linux.

### Security

- testenv: under `Contain` on Linux, the namespace's init dropped its capabilities on one thread and could start the tests from another, which still held `CAP_SYS_ADMIN` in its ambient set, so the tests and every program they started could hold it. Init now drops them and starts the tests from one locked thread. The bounding set, the securebits and the not-dumpable init above come with this fix.

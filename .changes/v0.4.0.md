## v0.4.0 - 2026-11-18

Thirty-three names are added, two are removed with no alias, and none is moved. The removed names are both in `proc`: `proc.Cmd.NoTerminal`, whose place `proc.Cmd.Terminal` takes with the opposite default, and `proc.Limits.Memory`, whose place `proc.Limits.ProcessData` and `proc.Limits.TreeMemory` take. A new package, `load`, is added. `gitenv`'s names and behaviour do not change. The tagged tree is 9,869 non-test Go lines outside `internal/` (`task size`), under the ceiling of 9,870.

### Breaking for a v0.3.0 caller

- `proc`: the zero `Cmd` gives the program no terminal of the caller's.
  - `Cmd.NoTerminal` is removed and `Cmd.Terminal` takes its place, with no alias. A caller that set `NoTerminal: true` now sets nothing. A caller that relied on the program getting its terminal, or on Windows its console, sets `Terminal: true`.
  - So a zero `Cmd` whose `Stdin` is a terminal, a console, or the pipe of an MSYS or Cygwin pty is now refused, wrapping `ErrRefused`, as one with `NoTerminal` was. A run with `Terminal` asks nothing of its `Stdin`.
  - `Detached` is unchanged: it starts with no terminal, as before.
- `proc`: `Limits.Memory` is removed, with no alias. It held two different things: each process's data segment on Linux, and the memory the whole tree commits on Windows. A caller picks one of the two new fields: `Limits.ProcessData` on Linux, `Limits.TreeMemory` on Windows.
- `service` on Windows keeps no file of a task.
  - `Folders()` answers an empty list and no error there, and a Windows plan's one `File` leaves `Path` empty. A `Path` that is set is refused, wrapping `ErrUsage`.
  - `Install` writes the task's XML to `task.xml` in a new folder of the system's temp folder, has `schtasks /create` read it there, and removes the folder whether or not schtasks took the task. `Remove` deletes the task and no file.
  - A `go-proc\service\<name>.xml` that v0.3.0 wrote under the user's local application data is no longer read or removed, so the caller may delete it.
- `service`: `Plan.Name` refuses, on every system, a name that ends in `.` and a name whose part before its first `.` is a Windows device name, in any case: `CON`, `PRN`, `AUX`, `NUL`, `COM0` to `COM9`, `LPT0` to `LPT9`. v0.3.0 took them.
- `testenv`: `Main` no longer reads a `windows-skips.txt` at the module's root. A module that kept one passes its names to the new `SkipOnWindows`. The file was read before the tests ran, outside go test's cache key, so an edit to it replayed an old result.
- `testenv`: `Isolate` and `Main` no longer force `GOWORK=off`. A run's `GOWORK` passes or leaks as `Keep` and `Drop` say, like any other name, and with neither it leaks, so a test's go finds a workspace as go does. A module that wants none sets `GOWORK=off` before `Main` and passes `Keep("GOWORK")`. `GIT_CONFIG_NOSYSTEM=1` and go's telemetry off stay, as safe defaults of the isolation.

### Refusals a caller now meets

Each is made before any program starts, unless it says otherwise.

- `proc`, wrapping `ErrRefused`:
  - a zero `Cmd` whose `Stdin` is a terminal, a console or an MSYS or Cygwin pty's pipe (above);
  - a negative `Cmd.Drain`, and a `Drain`, its zero default included, that with `Grace` passes the longest `time.Duration`;
  - `Limits.TreeMemory` on any system but Windows, and `Limits.ProcessData` on any system but Linux, each wrapping `errors.ErrUnsupported` too;
  - an entry of `Cmd.ExtraFiles` that is nil or a closed file, on every system;
  - on Linux, `Cmd.ExtraFiles` with a run that starts through the wrapper (`ReadPeak` or `Limits.ProcessData`), since the wrapper takes descriptor 3 and on for itself;
  - a set `Cmd.File` on any system but Linux, wrapping `errors.ErrUnsupported` too;
  - on Linux, a `File` with `Path`, a `File` that begins with `#!` or whose start cannot be read, a `File` with a run through the wrapper, and a run with a `File` when `/proc` is not a proc mount itself, a link to one included, as a file by that name there would run in its place (this last wrapping `errors.ErrUnsupported` too).
- `testenv`, wrapping the new `ErrRefused`: a `Rerun` or `RerunInterrupted` whose `ctx` has no deadline, or whose `outputCap` is below 1.
- `testenv`: a name given to `SkipOnWindows` that is not a top-level test's refuses the run.
- `service`, wrapping `ErrUsage`: on Windows a plan's `File` with a `Path`, and on every system a name that ends in `.` or is a Windows device name (above).
- `sandbox` on macOS: a profile or parameter the sandbox refuses is now an error that matches `ErrNoBlock`, with the sandbox's own first line, and the caller's program is not run. This one is made after a program starts: a dry run that starts only `/usr/bin/sandbox-exec` around `/usr/bin/true` (below).
- `load`: every system but Linux and macOS, and a source that cannot be read or parsed, return `ErrNoAverage`, which matches `errors.ErrUnsupported`.

### proc

- Added: `Cmd.Drain`, how long a run reads its output pipes after its tree is killed before it ends with `escaped`. It used to be a fixed 10 s.
  - A zero `Drain` is the default, 10 s, so a caller that sets nothing runs as before.
  - `Drain` bounds only the read of a pipe a process still holds, and is at least a quarter second there. A run whose tree left nothing holding its output pipes reads them to their end and ends without `WhyEscaped`, whatever `Drain` is, so a short `Drain` never cuts that output. A process started at the same moment for another run, which holds a copy of the pipe until its program begins, does not end the run as escaped.
  - A member the kill ended that still holds a pipe past the wait ends the run with `WhyEscaped` and `Left` true. With a `Drain` of 10 s or more, such a run no longer also ends with an `invalid argument` error, which came from asking again at the end of the wait about the pipe whose read the drain had already cut.
  - `Drain` never lengthens `Timeout`: `Run` returns at most `Timeout`, `Grace` and `Drain` after the program starts. On Unix a tree no signal reaches is waited for `Grace` and `Drain` past the kill, then left with `unkillable`.
- Added: `Limits.TreeMemory`, the memory the whole tree commits, held on Windows by the job, and `Limits.ProcessData`, each process's data segment (`RLIMIT_DATA`), held on Linux by the wrapper. The README has a table of what each limit holds on each system.
- Added: `Cmd.ExtraFiles`, open files the program inherits beyond its three streams.
  - On Unix entry i is its descriptor 3+i, as `exec.Cmd.ExtraFiles` gives it.
  - On Windows each handle goes to `AdditionalInheritedHandles` as it is. The caller marks it inheritable and tells the program its value.
- Added: `Cmd.File`, the program as an open file, so a file renamed over its name after it was opened is not the one that runs.
  - Linux alone runs one. The child execs `/proc/self/fd/<n>`, as glibc's `fexecve` does, with the file handed on after `ExtraFiles` and argv[0] its name.
- Added: `ErrBatch` and `ErrNotProgram` are exported. They are the refusals on Windows, by `Run` and `Start`, of a `Path` that names a batch file (`.bat` or `.cmd`) and of one that names no program file (`.exe` or `.com`), as given or as `PATHEXT` finds it.
  - Each wraps `ErrRefused` and neither matches the other, so a caller words each with `errors.Is` and no code of its own for Windows.
  - Both are declared on every system; off Windows no run returns either. What is refused does not change.
- Changed: a run's `Stdin` is told from a terminal by `golang.org/x/term`'s `IsTerminal`, in place of proc's own termios read and console-mode call. The MSYS and Cygwin pty pipe check is unchanged.
- Fixed: on Linux a program run with `Limits.ProcessData` or `Cmd.ReadPeak` starts with the signals its caller ignores ignored, as one run with neither does. Under v0.3.0's wrapper it started with `SIGTERM`, `SIGQUIT`, `SIGUSR1` and `SIGPIPE` at their defaults.
- Fixed, Windows: a run whose program starts nothing no longer reads `Left` true, at times on a loaded machine, when a process of its job ends between the job's listing of it and its opening.
  - Windows reads no image of a process that has ended while a handle to it is held (`ERROR_GEN_FAILURE`), nor, for some milliseconds, of one that has begun to exit (`ERROR_ACCESS_DENIED`).
  - The first is now taken for gone, as a pid no process has is, once its handle says it has ended. The second is waited for, as a console host is, once its exit code says it has begun to exit. In both, the job's count read again decides.
  - A process whose image cannot be read while its exit code says it is active is still left.
- Security: a run whose `Cmd.Stdin` is a nil `*os.File`, or a closed one, gives the program the null device, as a nil `Stdin` does. On Windows the program's stdin was a handle to the caller's own process, and on Unix it started with fd 0 closed, so the first file it opened was its stdin.
- Security: a `Detached` whose `Output` is a closed `*os.File` gives the program the null device for its stdout and stderr, as a nil `Output` does. On Windows they were a handle to the caller's own process, and on Unix the program started with fds 1 and 2 closed, so the first files it opened were its output.
- Security, Windows: the pipes a run makes for its program's stdin, stdout and stderr are no longer inheritable in the caller.
  - A process the caller starts another way during the run, handing on every inheritable handle, now holds none of them.
  - It used to hold the output pipes open, so the run ended with `WhyEscaped` and its output cut, and the stdin pipe, so the program did not see the end of its input.
- Security: a value stored in an exported error var, nil included, by a caller or a dependency, no longer changes what a gate refuses. Each gate returns, wraps and matches the value the var was built with.
  - `proc.ErrStale = nil` let `Stop` signal a process that took a reaped leader's pid.
  - The same holds for `proc.ErrRefused` and for the vars of `sandbox`, `service` and `load` (below).
  - No name or text changes. While no value is stored, `errors.Is` matches as before. After a store, a refusal matches the value the var was built with, not the one stored.
- Not held, Linux: a run through the wrapper, one with `Limits.ProcessData` or with `ReadPeak` armed, starts the wrapper from `/proc/self/exe` and, unlike a run with `Cmd.File`, does not check that `/proc` is a proc mount. In a root whose `/proc` is not the kernel's, whatever that path holds runs as the wrapper, so set neither there unless you would trust it as the wrapper.

### load (new)

- Added: `load.Read` reads the system load average: the one, five and fifteen minute averages, and `CPUs`, the CPU count.
  - Linux reads it through `github.com/shirou/gopsutil/v4/load`'s `Avg`, and falls back to `sysinfo(2)` when `/proc/loadavg` fails. It pins gopsutil's folder to `/proc` whatever `HOST_PROC` says.
  - macOS reads the `vm.loadavg` sysctl itself, since gopsutil's macOS build brings purego's `fakecgo` into every importer.
  - Windows, every other system, and a source that cannot be read or parsed return `load.ErrNoAverage`, which matches `errors.ErrUnsupported`.
  - It sets no threshold and starts no program.
- Security: a value stored in `load.ErrNoAverage` no longer changes what `Read` returns (as in `proc`).

### testenv

- Added: the package's test helpers.
  - `NoLeaks`, a run's leak check from the runtime's `goroutineleak` profile.
  - `Link`, `Links` and `NoLinks`: a link a test plants, or skips for by one message.
  - `Repo` and `GitPath`: a committed repository with links through git's index.
  - `Rerun`, `HelperTest`, `Helper`, `Signal` and `ErrEnded`: the helper-process practice. `Rerun(ctx, outputCap, args...)` takes both of its child's bounds from the caller, a deadline and a cap on each stream. A child that writes more than `outputCap` bytes to one stream is ended, with code -1, what it wrote up to the cap, and an error that is `ErrOutputCap`. `ErrRefused` and `ErrOutputCap` are new.
  - `TESTENV_HELPER` joins the names `Main` keeps.
- Added: `RerunInterrupted(ctx, outputCap, args...)` runs a helper as `Rerun` does, under the same bounds, and sends it the system's interrupt once it says it is ready with `Ready()`.
  - The interrupt is SIGINT on Unix, and CTRL_BREAK_EVENT to a process group of its own on Windows. Go hands it to the child as `os.Interrupt` on both, so a test of what a program does when interrupted needs no build tag.
  - A child that ends before it is ready, or that the interrupt cannot reach, gives the new `ErrNotInterrupted`.
- Added: `SkipOnWindows(names...)`, an option of `Main`, skips the named top-level tests on Windows from the caller's own code and runs them elsewhere. It replaces `windows-skips.txt` (above).
- Added: `Scale(t, base, limit)` stretches a test's wait by ten under `-race`, and by the one-minute load over the CPUs when that is above 1 (by race alone where `load` has no average). It is capped at `base * limit` and at `t.Deadline()`, and is never below `base`.
- Changed: `Git` takes its stripping from `gitenv.Env`, so a test's git child gets no `HOME`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH` or `XDG_CONFIG_HOME`, beside no `GIT_` name but its own.
- `testenv` now imports `load` and `gitenv` of this module.

### service

- Changed: `Plan.Name` takes up to 230 bytes, where it took 128. 230 is the longest name Task Scheduler creates, as measured on Windows 10.0.26200, and every unit, plist and task file built from it fits. The characters it refuses are unchanged.
- Security: `Plan.Name` refuses a name that ends in `.` and a Windows device name, on every system (above).
  - Task Scheduler keeps a task as a file of its name. The package follows Win32's file naming rules, which drop a last `.` from a file name and read a device name, with or without an extension, as the device.
  - A native run on Windows 10.0.26200 found that schtasks keeps `app.` and `app` as two tasks. So this is the rule followed, not a collision seen.
- Security: a value stored in `service.ErrAbsent`, `service.ErrPercent` or `service.ErrUsage` no longer changes what is refused. `service.ErrAbsent = nil` gave a system with no tool an empty tool and no error.
- Not held, Windows: `Install` writes the task's XML to a new folder below the temp folder Go's `os.TempDir` gives (`TMP`, then `TEMP`, then `USERPROFILE`, and `C:\Windows\SystemTemp` for a process running as SYSTEM), and schtasks reads it there by path. The file is made new, so one already there fails the install, but the folder takes the temp folder's access: an account that may modify what is made below it can change the XML before the task is registered. Keep the temp folder private to the user.

### sandbox

- Fixed, macOS: `Run` and `RunHolding` set their profile in a dry run of `/usr/bin/sandbox-exec` around `/usr/bin/true`, through `proc.Run`, before the exec. A profile or parameter the sandbox refuses is now an error that matches `ErrNoBlock`, with the sandbox's own first line, and the program is not run. It used to be the sandbox's exit, 65, after the exec, which read as the program's own.
- Security: a value stored in `sandbox.ErrUsage` or `sandbox.ErrNoBlock` no longer changes what is refused. `sandbox.ErrUsage = nil` let `sandbox.Run` take a line it refuses.

### For programs that import go-proc

- The module requires two new modules: `golang.org/x/term` v0.47.0 (for `proc`) and `github.com/shirou/gopsutil/v4` v4.26.10 (for `load` on Linux). gopsutil brings in `github.com/ebitengine/purego`, `github.com/go-ole/go-ole`, `github.com/power-devops/perfstat` and `github.com/yusufpapurcu/wmi` as indirect requirements.
- The lint bans of `.golangci.yml` and of the library picks each state their security or correctness reason, and those whose reason was a preference are lifted.
  - These may now be imported: `howett.net/plist`, `github.com/rogpeppe/go-internal/testscript` and, in tests, `github.com/stretchr/testify` and `gotest.tools` (`testify/mock` stays denied).
  - `github.com/elastic/go-seccomp-bpf` stays denied, for two security reasons. Its arch guard falls through to the default ALLOW for i386 and AArch32, and it compares ioctl's request on 64 bits, which lets `TIOCSTI|1<<32` through. `golang.org/x/net/bpf` stays allowed.
  - `go-cmd/cmd`, `k8s.io/utils/exec`, `go-winjob`, `jobobject`, `kardianos/service`, `takama/daemon`, `libseccomp-golang`, `tailscale/wf`, `criyle/go-sandbox`, the clocks `benbjohnson/clock`, `clockwork` and `quartz`, `go-isatty` and gopsutil's `process` stay denied, each for its stated reason.

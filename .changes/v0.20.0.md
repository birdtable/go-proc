## v0.20.0 - 2026-11-28

One type is added, in `proc`: `EndKind`, with its four values `EndExited`, `EndSignal`, `EndAbnormal` and `EndNone`, and `Result` gains three fields, `End`, `Signal` and `Status`. No name is removed or moved, and no signature changes: the API check finds no break since v0.19.2. Every name added is experimental, as every name of the module is. Five promises are added to `api/contract.txt` and none changes, and v0's API may change between minor versions, so this is a minor release. What a name does changes in two places, both on Linux under glibc: under glibc 2.37 or older, or a glibc whose release cannot be told from its loader's file, `sandbox.RunHolding`, and `sandbox.Check` with folders, now refuse up front some programs that v0.19.2 ran, which breaks some callers; and they now run a program v0.19.2 refused only for a file named like a subfolder glibc looks in first, which glibc passes over. The Security entry names each. Under musl nothing changes, and under glibc 2.38 or later one thing does: a file, not a folder, named `glibc-hwcaps` in a folder the search looks in no longer refuses the program. Of v0.19.2's list of loads not promised refused up front, a hwcap subfolder that glibc up to 2.36 reads under a widened mask leaves it, and one is left in the docs: a library found where a loader's search order differs from the search's in some other way. What the block enforces does not change. In `proc`, `Code` and a run's error do not change. Nothing changes in `service`, `load` or `gitenv`, and no require in go.mod changes. The tagged tree is 12,382 non-test Go lines outside `internal/` (`task size`), at its ceiling of 12,382, up 98 (0.8%) from v0.19.2's 12,284: 74 for `Result.End` and 24 for the glibc changes. The full release checks ran on macOS at the tagged commit; vet and the tests, with the race detector, ran on Linux, macOS and Windows at the tagged commit in CI. No full release checks ran on Linux or Windows for this release.

### For a v0.19.2 caller

In `proc`, a v0.19.2 caller needs no change: `Code` and a run's error read as before, and `Result.End` now says how the program ended, `EndNone` where go-proc refused or ended the run, a Contained run whose program its kill on a lost limit ended among them, or its wait for the program failed. On Linux, nothing changes in `sandbox` for a program that does not call `sandbox.RunHolding`, or `sandbox.Check` with folders, or whose loader is musl; under glibc 2.38 or later the one change is a file named `glibc-hwcaps`, below. Under glibc 2.37 or older, or a glibc whose release cannot be told from its loader's file, a program is now refused with `ErrUsage` before anything is set, where v0.19.2 ran it, when a folder list the search walks before it finds a library holds a folder whose written path is 4,095 bytes. On arm64, under glibc 2.36 or older, or a glibc whose release cannot be told, a program is refused too when a folder the search looks in has a subfolder named for a hwcap bit outside glibc's default mask, such as `asimd` or `cpuid`, whose real path is beneath no built-in folder of its loader. Such a program runs only once its libraries are reached by the search order alone. Under glibc, a program v0.19.2 refused only because a folder the search looks in held a file, not a folder, named `glibc-hwcaps`, `tls` or for a platform or hwcap bit, now runs, as glibc passes such a file over. Callers on macOS and Windows see no change in `sandbox`.

### Added
* proc: `Result.End` says how the program ended, as far as its system can tell: `EndExited`, its own exit, with `Code`; `EndSignal`, an end by a signal go-proc did not send, with `Result.Signal` naming it (Linux, macOS and the other Unix systems); `EndAbnormal`, an exit code of 0xC0000000 and above, an NTSTATUS error value such as an access violation, with `Result.Status` (Windows); and `EndNone` for a run go-proc refused or ended, a Contained run whose program go-proc's kill ended once its cgroup lost its limit among them, whose error says why, as before; a program that exited before the loss was read keeps `EndExited` and its `Code`. On Windows a program another process ends by `TerminateProcess` with a code below 0xC0000000 reads `EndExited` with that code, and one ended with a code at or above it reads `EndAbnormal`: the system keeps no mark of who chose the code. An unhandled exception of warning severity, below 0xC0000000, such as STATUS_BREAKPOINT (0x80000003) or STATUS_GUARD_PAGE_VIOLATION (0x80000001), reads `EndExited` with that code too. `Code` and the error do not change.

### Security
* sandbox: on Linux, under glibc 2.37 or older, or a glibc whose release cannot be told from its loader's file, the load search now asks whether a folder in a list is there without its closing slash, as glibc up to 2.37 does, and with it from 2.38. So a folder whose written path is 4,095 bytes, at the kernel's length limit, where the library's path is past it, is now refused under those, as glibc up to 2.37 ends the list there, where v0.19.2 passed it over; from 2.38 it is still passed over, as glibc passes it over. A file there is still passed over under every release, as glibc's stat finds no folder. The root in a list is still asked as itself, though glibc up to 2.37 passes it over, which fails closed. On arm64, under glibc 2.36 or older, or a glibc whose release cannot be told, a folder the search looks in is now refused when a subfolder named for any hwcap bit glibc knows, `asimd`, `aes`, `sve` and the rest, has a real path beneath no built-in folder of the loader, not only one of the default mask's: the caller widens the mask in the program's environment by `LD_HWCAP_MASK`, or by `GLIBC_TUNABLES` with `glibc.tune.hwcap_mask` from 2.26 to 2.28 or `glibc.cpu.hwcap_mask` from 2.29, and `sandbox.Check` is given no environment, so every name is judged whatever the mask. `cpuid`, the default mask's name before `atomics`, is among them. Under any glibc, a file, not a folder, named `glibc-hwcaps`, `tls` or for a platform or hwcap bit, now no longer refuses the folder it is in, where v0.19.2 refused it: glibc stats each such subfolder and passes over one that is no folder. A name whose real path cannot be told still refuses it, as whether it is a folder cannot be told either. Of v0.19.2's list of loads not promised refused up front, a hwcap subfolder read under a widened mask leaves it. What the block enforces does not change. Breaking: each program this entry names as refused is now refused, where v0.19.2 ran it.

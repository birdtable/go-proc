## v0.12.0 - 2026-11-21

Two things are removed, as `api/breaks/v0.11.0.txt` lists them: `gitenv.Without` and the package `testenv`. testenv's names move to `github.com/birdtable/go-testkit`, its containment to `github.com/birdtable/go-testkit/contain`, and its three git helpers to the new package `gitenv/gittest`; the list by package is below. Four names are added to `proc`: `Interrupt`, `PathList`, `LocalPathList` and `ErrPathElement`. Every name added is experimental, as every name of the module is. In `sandbox` only the macOS block's marking of descriptors changes, a security fix below; nothing changes in `service`, and in `load` only its README. go.mod requires one module more, `github.com/birdtable/go-testkit v0.2.0`, for go-proc's own tests and for `gitenv/gittest`, a package for tests; a program that imports neither links none of it; no module is dropped and the others keep their versions. The tagged tree is 10,410 non-test Go lines outside `internal/` (`task size`), at its ceiling of 10,410, raised by 15 for that fix alone, down 2,561 from v0.11.0's 12,971: the runtime packages are 10,410, up 754 from 9,656, and `testenv`'s 3,315 lines have left the module.

### For a v0.11.0 caller

- A test that imports `github.com/birdtable/go-proc/testenv` no longer builds. It changes its import, and for the names below a name, but not what the name does, except `Scale`, which takes one more argument.
- A caller of `gitenv.Without` writes the drop itself, as the Removed entry under gitenv shows.
- A `Limits.Contained` run on Linux is refused, and its tree killed, in three cases where it started before: a thread of the run holds a descriptor on a cgroup file system or a mount namespace, the run's cgroup does not read back `memory.swap.max` `0` and `memory.oom.group` `1`, or a cover over a cgroup mount is missing when the run says it is ready. It is no longer refused where the caller's cgroup mount root lies above its cgroup namespace's root. The Security entries below say each one.
- A `Limits.Contained` run is charged the caller's own binary for a moment as its program starts: about 13 MiB for a plain go-proc test binary, about 48 MiB for a race-built one. A `TreeMemory` leaves that room beside what the program holds.

  - To `github.com/birdtable/go-testkit` with one more argument: `Scale(t, base, limit, load)`, as the entry under testenv shows.

### proc

- Added: `Interrupt(id TreeID) error` asks a tree `Start` started to stop, and kills nothing. On Linux and macOS it sends one SIGINT to the tree's process group. It checks the id first, as `Stop` does and in the same order: an id `Start` did not give here is refused as `Stop` refuses it, and one whose leader is gone or reaped is `ErrStale`, and neither is signalled. On Windows it sends nothing and the tree runs on, with an error wrapping `errors.ErrUnsupported`: a tree `Start` makes has no console, and a CTRL_BREAK_EVENT reaches only processes that share the sender's. The caller waits, and stops the tree after, itself; the package example shows both.
- Added: `PathList(goos, dirs...)` and `LocalPathList(dirs...)` join folders into a PATH value for a child, so the child reads back the same folders in the same order. A folder that can't be one element is refused with an error wrapping the new `ErrPathElement`, which names the folder and its place, and nothing is joined. On every system that is an empty name or one holding a NUL; on Linux and macOS one holding `:`; on Windows one holding `;` or `"`, where no quotes are written. `strings.Join(dirs, string(filepath.ListSeparator))` would turn a folder named `a:b` into two on Linux and macOS, and on Windows one holding `;` into two, the second relative. Each folder is otherwise written as given; which folders belong on the list is still the caller's choice.

### gitenv

- Removed: `Without`, with no forwarding name: the standard library does its whole job on every system. `Env`, `Repo` and `ReadArgs` are unchanged. A caller that dropped variables by the start of their name writes it itself:

    ```go
    out := slices.DeleteFunc(slices.Clone(environ), func(kv string) bool {
        name, _, _ := strings.Cut(kv, "=")
        return strings.HasPrefix(name, "GIT_")
    })
    ```

    The `slices.Clone` is needed: `slices.DeleteFunc` changes the slice it is given and zeroes its tail, so without the clone the caller's own `environ` is damaged. Like `Without`, this compares the name as written, on every system. The drops that ignore case are `Env`'s and `Repo`'s, and they stay.
- Added: the package `gitenv/gittest`, for tests, holds `Git`, `Repo` and `GitPath`, moved unchanged from testenv. A caller changes its import:

    ```go
    import "github.com/birdtable/go-proc/gitenv/gittest"

    env := gittest.Git(t.TempDir())
    repo := gittest.Repo(t, files, nil)
    ```

    The environment `Git` gives, the identity it commits under and the branch `Repo` commits on are as they were. gittest imports testkit for `Clean`.

### testenv

- Removed: the package, with no forwarding path. It is `github.com/birdtable/go-testkit` now, a module of its own whose root imports the standard library alone. go-proc requires it for its own tests only. A test file changes its import:

    ```go
    import "github.com/birdtable/go-testkit"

    func TestMain(m *testing.M) {
        code, err := testkit.Main(m)
        if err != nil {
            panic(err)
        }
        os.Exit(code)
    }
    ```

    `Scale` takes one more argument, the caller's load reading: the one-minute average over the CPUs this process can use, or 0 for none, as on Windows. testkit reads no load itself. To keep what `testenv.Scale` did:

    ```go
    perCPU := 0.0
    if r, err := load.Read(); err == nil && r.CPUs > 0 {
        perCPU = r.One / float64(r.CPUs)
    }
    wait := testkit.Scale(t, time.Second, 30, perCPU)
    ```

    A test binary that was given `testenv.Contain` takes `contain.Contain()` from `github.com/birdtable/go-testkit/contain` and passes it to `testkit.Main`. go-proc keeps its own list of the home variables for `proc.HomeEnv`, and a test of go-proc's fails when it differs from the list testkit isolates.

### The surface and its files

- Changed: `API.txt` is gone, and with it go-proc's own checker of it. The whole exported surface at a tag is `go doc -all github.com/birdtable/go-proc/<package>@<tag>`, which needs no checkout. `api/marks.txt` lists the names that are not experimental: none today, so every exported name is experimental, as before. `task api`, in the push and release tiers, holds the surface with apidiff on darwin, linux and windows: the three alike but for what `api/systems.txt` lists (nothing), and the breaks since the last tag equal to `api/breaks/<tag>.txt`.
- Added: `api/contract.txt` holds the promises a product may rely on, each naming the test that holds it and the systems it is about. The tests of `internal/contract` hold it: each line's test is declared, built and not skipped on the systems its line names; the index is sorted with no test twice; and a promise removed or changed since the last tag is listed in `api/breaks/<tag>.contract.txt`. The format is the one birdtable's Go libraries share.
- Fixed: NOTICE no longer lists `github.com/containerd/cgroups/v3` and the seven modules it brought, which go.mod dropped in v0.8.0. It names `github.com/birdtable/go-testkit`, says which packages import `golang.org/x/sys` on which system, and no longer names testenv among the packages that came from the earlier module. The release tier's notice-check now fails when NOTICE and the build disagree.

### Security

All but the last are in `proc`, about a `Limits.Contained` run on Linux; the last is in `sandbox`, on macOS.

- The covers the shim puts over the cgroup mounts are now read back when the run's report says ready (v0.8.0 said they were not). The caller freezes the run's cgroup, reads each of its threads, and each cgroup below it, for the cover by mount id and parent id, with the cover's root at the run's cgroup as the caller sees it, and thaws it after. So a program that skipped the shim, dropped its capabilities, set `no_new_privs` itself before it wrote the ready byte and left a cgroup mount open is refused, and its tree is killed. A task that is ending counts as gone; a thread-group leader that ended alone is gone for itself, and its other threads are read; a cgroup that can't be frozen refuses the run. The shim now ends in a second stage: the caller's binary started again once `no_new_privs` is set and no capability is left, so every thread the caller reads began with neither. That stage starts the program only when the caller, its check passed, tells it to, so the check never reads a step of the program's. What it does not see: a user namespace of the program's that rebuilds the cover's shape and root from the caller's mount; a descriptor on the caller's cgroup tree that a process of the same user outside the tree hands to the program after ready; a write before ready to a cgroup other than the run's, which survives the refusal and the kill; and a reference to the caller's cgroup mount that a start which skipped the shim keeps as a working directory, a root, a detached clone of a mount above it, or a descriptor in flight in a socket pair the tree holds. A second process of the same user, outside the run's cgroup namespace, can move a process of the run to another of the user's cgroups: it is charged there, so the run's memory limit does not hold for it while the move lasts, and the tree's kill still reaches it through the run's pid namespace. The charge of the caller's binary as the program starts is in the section for a v0.11.0 caller.
- The run is now refused, and its tree killed, where the check at ready finds a descriptor on a cgroup file system, of either version and wherever it is mounted, or on a mount namespace, in any thread of the run's cgroup. Each thread's own descriptors are read, so a thread with a file table of its own is read too, and the error names the thread, the descriptor's number and what it is on. A caller that hands such a descriptor to the run is refused, as one that hands a directory already was. A descriptor that a process outside the tree hands back after ready is not seen.
- The check of the run's limit now reads back every file the run wrote, not `memory.max` alone: `memory.swap.max` must read `0` and `memory.oom.group` `1`, or the run ends with an error naming the file and what it reads, and its tree is killed. A write before ready to a cgroup other than the run's still survives the refusal and the kill.
- The run is no longer refused as forged where the caller's cgroup mount root lies above its cgroup namespace's root, as for a caller that unshared a cgroup namespace without mounting cgroup2 again. The leading `..` parts of the mount root are now cancelled by as many leading parts of the path below the mount. A run that lies outside the caller's namespace, which the kernel does not let the caller place, is still refused.
- The shim asks for its ambient capability before it touches its report. A start that gives it none, as a setuid or file-capability exec of a binary that imports proc does, now exits 127 having written nothing and closed no descriptor, where before it wrote two fixed bytes to the descriptor its arguments named, which could be one an earlier `init` of that binary opened.
- The macOS block no longer hands the program a descriptor another goroutine of the caller holds open as the block is set, nor a pipe or a new socket one makes then. This affects `sandbox` on darwin only, in every tag from v0.1.0 to v0.11.0; a darwin caller should upgrade to v0.12.0. The block found the descriptors to mark by listing /dev/fd with `os.ReadDir`, which stats each entry and leaves out one whose stat says EBADF; while other goroutines look up /dev/fd at once, that stat now and then says EBADF of a descriptor held open, so one could stay unmarked and reach the sandboxed program. The listing is now read by its names alone, which stats nothing. And macOS makes a pipe or a socket and marks it in two calls, so one another goroutine made between the last marking and the exec could reach the program too; the block now holds `syscall.ForkLock`, under which Go makes them, from that marking into the exec. One class stays, since the exec stops no other goroutine: any descriptor another goroutine makes or receives without `syscall.ForkLock` after the last marking can still reach the program, on macOS one from `Accept`, a received `SCM_RIGHTS` message or a raw `dup`, and on Linux, where Go marks the others as it makes them, a raw `dup`. A caller with such goroutines calls `Run` from a process that has none; `posix_spawn` on macOS, which closes the class in the kernel, is planned. Linux makes and marks a pipe or a socket in one call and marks by `close_range`, in every tag, and is not affected by either path.

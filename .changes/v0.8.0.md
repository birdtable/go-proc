## v0.8.0 - 2026-11-20

Twenty-six names are added: five in `proc` (`DefaultDrain`, `FileName`, `HomeEnv`, `Needed`, `NeutralDir`), one in `sandbox` (`ErrNoSystem`) and twenty in `testenv`. Two names are removed, both from `testenv`: `Environ` and `Lookup`, with no alias. One signature changes: `testenv.Signal` returns an `os.Signal` where it returned a `syscall.Signal`. Every name added is experimental, as every name of the module is. Nothing changes in `gitenv`, `load` or `service`. go.mod no longer requires `github.com/containerd/cgroups/v3`, and with it seven indirect modules go: `github.com/cilium/ebpf`, `github.com/containerd/log`, `github.com/coreos/go-systemd/v22`, `github.com/godbus/dbus/v5`, `github.com/opencontainers/runtime-spec`, `github.com/sirupsen/logrus` and `google.golang.org/protobuf`. No require is added and no version changes. The tagged tree is 12,339 non-test Go lines outside `internal/` (`task size`), at its ceiling of 12,339, up 1,605 from v0.7.0's 10,734: 9,609 in the runtime packages and 2,730 in `testenv`.

### For a v0.7.0 caller

- `testenv.Environ()` and `testenv.Lookup(name)` are gone. They were exactly `os.Environ()` and `os.LookupEnv(name)`, so call those; under `testenv.Main` they read the environment `Main` made, as before.
- `testenv.Signal(err)` returns an `os.Signal`. With no signal it returns nil and false, where it returned 0 and false. A caller that compares the result with `syscall.SIGKILL` still compiles; one that keeps it in a `syscall.Signal` variable, or compares it with a number, changes.
- A zero `Cmd.Drain` now means `DefaultDrain`, one second, on every system. On Unix a zero `Drain` read nothing past the kill, and on Windows it was refused. A run that is killed may now take up to a second longer to return, and keeps the output read in that second. A caller that wants no read past the kill gives a `Drain` of one nanosecond. A negative `Drain` is still refused.
- `testenv.Isolate` sets the variables `proc.HomeEnv` sets: on Unix it no longer sets `USERPROFILE`, `APPDATA` or `LOCALAPPDATA`, and on Windows it now sets `HOMEDRIVE` and `HOMEPATH`.
- On Windows, a `Grace` above zero on a run with `Terminal`, from a process that has a console, is now held instead of refused. Every other Windows run with a `Grace` is refused as before.
- On macOS, the profile behind `sandbox`'s block now denies another process's task ports. A program behind it that read, inspected or named another process by its task port is refused that now.
- On macOS, `Stop` reports a tree as still running where one of its processes changed its user, as a command under sudo does. In v0.7.0 it answered nil for such a tree.
- On Linux, a `Limits.Contained` run where a security module (SELinux or AppArmor) refuses the user namespace with `EACCES` is refused wrapping `ErrNotHeld` and `errors.ErrUnsupported`. In v0.7.0 it was a hard refusal, so a caller that drops `Contained` where the host can't hold it now runs there.
- On Linux, a `Limits.Contained` run is refused where a seccomp filter refuses `openat2`, as the shim now enters its folder through it (see Security below). The shim already needed Linux 5.11, after `openat2`'s 5.6, so no kernel that ran it before is refused for this.
- On Linux, a `Limits.Contained` run whose `memory.events` has no `oom` line, is empty, or holds a count that isn't a number ends, with the limit lost. v0.7.0 read that as no oom.
- A program that imports `proc` links fewer packages on Linux, as go.mod above says.

### proc

- Added: `Needed()` names the variables `Bare` keeps for a child on this system.
- Added: `HomeEnv(root)` gives the variables that point a program's home, configuration, cache, state and temp folders at folders of their own beneath `root`: `HOME`, the five `XDG_` folders, `TMPDIR`, `TMP` and `TEMP` everywhere, and on Windows `USERPROFILE`, `APPDATA` and `LOCALAPPDATA`, with `HOMEDRIVE` and `HOMEPATH` naming the profile. Append them after an `Env` so each replaces its name. It makes no folder.
- Added: `FileName(goos, id)` is the file name a program has on a system: `id.exe` on Windows, `id` elsewhere. `goos` is an argument, so every system's name can be tested on any host. `Run` and `exec.LookPath` add `.exe` themselves when they look a program up; this is for code that writes, copies or links a program's file.
- Added: `NeutralDir()` is a folder that belongs to no project, `/` on Unix and the system drive's root on Windows, for a run that needs no working folder of its own. An empty `Dir` is still this process's folder, as in `os/exec`.
- Added: `DefaultDrain`, a second, is the `Drain` of a run whose `Drain` is zero (see above). It is there so that a process another run starts beside this one, which holds a copy of this run's pipes until it starts its own program, doesn't cut this run's output. A host that starts processes more slowly than that under load sets `Drain`.
- Changed: `proc` no longer imports `github.com/containerd/cgroups/v3`. On Linux it writes a run's `memory.max`, `memory.swap.max` and `memory.oom.group` and reads its `memory.events` and `memory.peak` itself.
- Changed, on Windows: a held `Grace` with `Terminal` sends the program's process group CTRL_BREAK_EVENT, holding the program's handle while it sends, then kills the job when the `Grace` runs out. A break that can't be sent kills the job at once, and the run's error says why. A process of the tree that made a process group or a console of its own gets no break and is killed with the job. `Holds` answers for each `Cmd`.
- Fixed, on macOS: `Stop` could answer nil while a process of the tree ran on, when the tree forked as the kill landed. `Stop` now stops the tree's process group with SIGSTOP before it sends SIGKILL. The cause was found by reading the code and the kernel's behaviour, not by reproducing it, and a narrower window remains, described in `Stop`'s doc.
- Fixed, on Linux: a `Limits.Contained` run whose tree wrote 0 to its `memory.oom.group`, and whose first process the kernel then killed for its limit, ends with `limit`. It ended as a crash before.
- Fixed, on Linux: a `Limits.Contained` run's shim retries its `fstat`, `getcwd` and `chdir` while one fails with `EINTR`, as a signal to the shim on a slow FUSE mount can make one fail. Such a run was refused before.
- Fixed, on Windows: the `ChildrenCPU` error points to `TreeUsage.CPU`, from `Usage` of the id `JoinTree` gives, which counts every process this one starts from then on and includes this process's own CPU time.
- Security, on Linux: a `Limits.Contained` start no longer enters `Dir`. The shim enters it after the start and then enters it again by its path, so an error from the start is never about the `Cmd`'s folder. A `Dir` the caller can't enter is refused by the shim, wrapping `ErrRefused` alone, as before, now with the shim's reason. So is a `Dir` reached through a proc link (`/proc/self/cwd` or `/proc/self/fd/N`) to a folder in a cgroup mount or on no mount of the tree's.
- Security, on Linux: a `Limits.Contained` run's shim no longer enters its folder again by a chdir to the path `getwd` gave. That gap, there since v0.6.0, let a writer to one of the folder's parents swap a folder for a link between the two calls, to a folder the caller holds open, `/proc/self/fd/N` among them. The program then started in that folder, which could be in the caller's cgroup mount, outside the covers, from where it could reach the caller's cgroup, freeze or kill the caller, and lift its own memory limit. It needed a caller that holds a folder open without close-on-exec and another process writing beside the start as it ran. The shim now opens the path by `openat2` with `RESOLVE_NO_SYMLINKS` and enters what it opened by `fchdir`, so a link at any part of the path is refused, wrapping `ErrRefused`, as a `Dir` the shim can't enter is. Where a filter refuses `openat2` the run is refused too, and the shim never falls back to a chdir by the path.
- Security, on Linux: a start that skips the shim is refused even where the program writes the shim's ready byte itself. Only an `init` function of the caller's own binary can skip the shim. When the shim reports ready, the caller checks that each process of the run's cgroup has `no_new_privs` set and holds no capability, as the shim leaves them, and kills the tree if one doesn't. A program that never writes the byte runs unheld to its end, as before. The caller doesn't read back the shim's covers over the cgroup mounts.

### sandbox

- Added: `ErrNoSystem` is matched by the error of `Run`, `RunHolding` and `Check` on a system that has no block at all, Windows and FreeBSD among them. Such an error still matches `ErrNoBlock`, with the same text. Where the system has the block but this host refused a step (on Linux an older kernel, Landlock turned off or no seccomp filter for the architecture; on macOS a system sandbox that couldn't start), the error matches `ErrNoBlock` alone and names the step. A caller can tell "no block on this system" from "this host refused a step" without reading the text.
- Security, on macOS: the profile denies another process's task ports, `(deny mach-priv-task-port)`. A program behind the block, signed with no entitlement, is refused the read, inspect and name ports of a process outside it, as measured. The control port, by which a debugger attaches and takes what that process holds, its sockets among them, falls under the same clause, but its refusal wasn't measured, and a caller signed with the debugger entitlement wasn't tried.

### testenv

- Added: `Binary.Install(t, folder, name)` copies the built program into `folder` as `name`, adding `.exe` on Windows, and returns its path, for a test that puts `folder` on its child's PATH. A name that isn't a single file name (empty, `.` or `..`, holding `/`, `\` or `:`, or a Windows device name such as `NUL`) is refused, and so is a name that's already there: nothing is replaced. A refusal, or a failed build, fails the test.
- Added: `Binary.Start(ctx, args...)` starts the program and returns a `*Running`, with `Interrupt`, `Kill` and `Wait`. `Interrupt` sends SIGINT on Unix, and CTRL_BREAK_EVENT to the program's own process group on Windows. `Kill` reports the program as killed, code -1, on every system. Once the program has ended, both send nothing and return `os.ErrProcessDone`. A `ctx` without a deadline is refused with `ErrRefused`.
- Added: `HoldRead(t)` gives a path that a reader opens without blocking, and whose read waits until the test calls `release`, which ends it with nothing read. The test's cleanup releases it too. On Unix it is a FIFO of mode 0600 in the test's own folder. On Windows it is a pipe in `\\.\pipe\`, in no folder, that only this account may open, once, from this machine; a second reader is refused.
- Added: `ShortDir(t)` gives a new folder, removed with the test, whose path is short enough for a socket's path on every system, leaving at least 40 bytes under it: in `/tmp` with mode 0700 on Unix, in `os.TempDir` on Windows. `SocketPathMax` is the most bytes a socket's path may hold on this system: 107 on Linux and Windows, 103 on macOS and the BSDs.
- Added: `Contain()` is an option of `Main` that reruns the whole test binary inside a containment before any test runs, so a signal a test sends reaches no process outside it. On Linux the binary runs as PID 1 of its own user and PID namespace, with a private mount and a fresh `/proc`, and reaps what its tests leave behind. On Windows it runs in a kill-on-close Job Object, in its own process group and a console with no window. `Contained(t)` checks the containment from inside the run and skips the test where there is none, with one of three reasons: `NotAsked`, `NoContainment`, or `Refused` followed by the system's words, as on a host that refuses user namespaces. A stray `TESTENV_CONTAINED` in the environment doesn't make a run contained. Tests that don't call `Contained` run uncontained where the containment is refused.
- Added: `Modes(t)` skips a test, with the message `NoModes`, on a system that keeps no file mode bits, as on Windows.
- Added: `OtherAccount(t)` returns the second ordinary account the host names in `TESTENV_OTHER_ACCOUNT` (`OtherAccountVar`), and skips the test with the message `NoOtherAccount` where none is set. It never creates an account.
- Added: `RerunVia` reruns the test binary behind a wrapper named by an absolute path, such as a sandbox.
- Changed: `Signal(err)` returns an `os.Signal` (see above).
- Changed: `Isolate` sets the same variables as `proc.HomeEnv` (see above).
- Removed: `Environ` and `Lookup` (see above).

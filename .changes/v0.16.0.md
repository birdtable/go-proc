## v0.16.0 - 2026-11-25

One function is added, in `proc`: `HoldsTreeMemory`, with its result type `TreeMemoryHold` and that type's three values. No name is removed or moved, and no signature changes: the API check finds no break since v0.15.0. Every name added is experimental, as every name of the module is. Nothing changes in `sandbox`, `service`, `gitenv` or `load`. In go.mod, go-testkit moves from v0.2.0 to v0.3.1, its public tag, for go-proc's own tests and `gitenv/gittest` alone; no other require changes. One fix, in `proc` on Windows, is under Security below. The tagged tree is 11,377 non-test Go lines outside `internal/` (`task size`), at its ceiling of 11,377, up 84 from v0.15.0's 11,293: 61 for `HoldsTreeMemory` and 23 for that fix. The release checks ran on macOS (arm64), Linux (amd64) and Windows (amd64).

### For a v0.15.0 caller

Nothing changes for a program that does not call `HoldsTreeMemory`, but for `Stop` and `Interrupt` on Windows: every other name gives what it gave. On Windows, `Stop` and `Interrupt` of a tree whose leader has exited and been reaped are `ErrStale`, as they are documented to be and are on Linux and macOS, where before they could still end the processes the tree left running (see Security). A caller that asked `Holds` twice to learn whether a memory cap is held, once with the cap and once without it, can make one call to `HoldsTreeMemory` instead.

### Added

* proc: `HoldsTreeMemory(c Cmd) (TreeMemoryHold, PeakKind, error)` says how this system holds `c`'s `Limits.TreeMemory`, without starting anything. `TreeMemoryHeld` means the system holds the cap, and the `PeakKind` says how the peak is read. `TreeMemoryJudgedAfter` means the system cannot hold the cap but can read the run's peak, a tree's charge on Linux or one process's peak on macOS and the BSDs, so the caller can judge the cap by it after the run. `TreeMemoryRefused` means neither. A refusal for any other reason comes back as `Run` would give it, and a `c` with no `TreeMemory` comes back with a refusal of its own. `Contained` is kept as given, so a `Contained` `c` whose cap is not held is refused, never judged after.

### Changed

* build: go.mod requires `github.com/birdtable/go-testkit` v0.3.1, the public tag of its repository, where it required v0.2.0. Only go-proc's own tests and `gitenv/gittest`, a package for tests, import it, so a program that imports neither links none of it. Nothing in go-proc's API changes with it: v0.3.1 is v0.3.0 with its docs and its own gate changed, and adds, removes or moves no name. The API check, `task api`, is go-testkit's at that version, and `Taskfile.yml` calls Go programs in place of shell pipes. No exported name and no behaviour of the library changes.
* docs: the README is one page: what go-proc is for, how to install it, a quick start the tests compile and run, what each package is built on and adds, the systems and what each refuses, and how to report an issue. Each package README has the same shape, and the full reference is in the doc comments on pkg.go.dev. `SECURITY.md` says how to report a vulnerability privately, and `CONTRIBUTING.md` how to run the tests and send a change.

### Security

* proc, on Windows: `Start` gave a tree's leader its handle of the Job Object as an inheritable duplicate in the caller's process, open from before the leader started until after it was resumed. A process another goroutine of the caller started meanwhile with every inheritable handle handed on, as `CreateProcess` outside `os/exec` may, took that handle too and kept the job named after the leader was reaped. `Stop` by the old id then ended the processes the tree had left running, and `Interrupt` answered the tree as live with `errors.ErrUnsupported`, both where `ErrStale` is documented. The handle is now duplicated straight into the suspended leader, not inheritable, so the caller never holds an inheritable handle of the job, and an id is stale once its leader is reaped. The leader's own children no longer inherit the handle either, so a tree whose leader exits while its children run is `ErrStale` to `Stop` and `Interrupt`, as the contract and Linux and macOS have it. Linux and macOS do not change, and no exported name changes.
